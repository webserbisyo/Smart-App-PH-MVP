## Goal

A guest can get a trusted price, place a walk-in, pickup or delivery order once (even when the phone retries),
upload a payment proof with a reference number that can never be reused in that shop, and watch the receipt
update live. Every amount and every stock change happens in the database.

### Mistakes in the reference not to copy

- It numbered the order before validating the lines; that is fine only because the whole function is one
  transaction. Keep it that way: never catch an exception after the counter moves unless you re-raise.
- It raised on the first bad line, so the cart could show only one problem at a time. `quote_order` must collect
  every line problem into `problems[]` and return; `place_order` raises the first.
- It wrote order events with a free-text `kind` and no `actor` check. Use the closed lists below.

## Build only

### 1. Migration `<timestamp>_orders.sql`

Tables (paper 7.3 columns; additions marked +), `tenant_id` on each, composite foreign keys to parents in the same
shop, RLS on:
- `customers`: unique `(tenant_id, phone)`; `user_id` references `auth.users on delete set null`, unique
  `(tenant_id, user_id)` where `user_id` is not null (one member row per login per shop);
  `member_since`, `order_count`, `total_spent`, `last_order_at`, `notes`, `tags text[] default '{}'`.
- `consents` (append-only; channel check `('privacy','sms','email','push')`).
- `orders`: unique `(tenant_id, business_date, order_no)`, unique `token`, unique `(tenant_id, client_key)`;
  status, payment status, payment method and fulfillment checks mirror `enums.ts`; `total = subtotal -
  discount_total + delivery_fee` as a check; + `expires_at timestamptz` (when an unpaid transfer order expires).
- `order_items` (`item_id` and `variant_id` reference the catalog `on delete set null`, and a `before delete`
  trigger on `items` raises `item_has_orders` when order lines point at it, so owners archive instead (paper 7.3); names and prices are
  snapshots; `options jsonb` array of `{optionId, name, priceDelta}`), line total check.
- `order_events`: + `kind text` check `('status','payment_submitted','payment_confirmed','payment_rejected')`,
  + `actor text` check `('customer','owner','system')` (closes decision P1-5); `from_status`/`to_status` null for
  payment events; + `note`.
- `order_counters` (pk `tenant_id, business_date`), no client access at all.
- `payments`: status check `('pending','confirmed','rejected')`; partial unique index on `(tenant_id,
  reference_norm) where status <> 'rejected'` (paper 6.4: a reference is usable once per shop); + `reviewed_by`.

Grants and policies: owners `select` on all of these (`is_shop_member`); owners `update (notes, tags)` on
`customers` while active; no other client writes (functions only); `anon` nothing.

Core contract updates (same commit): `OrderEvent` gets `kind` and `actor`; `Order` gets `expiresAt`;
`Customer` stays; error codes from slice 3 go into `contracts/errors.ts` with words.

### 2. Functions

All `security definer`, `set search_path = ''`, errors as fixed codes (`docs/api-surface.md` slice 3).

- `private.build_order(p_tenant_id uuid, p_payload jsonb, p_quote boolean) returns jsonb`: one engine for both
  calls. Order of work:
  1. Shape check of the payload (camelCase keys as `OrderPayload` sends them); bad input → `invalid`.
  2. Throttle (place only): at most 3 unpaid orders per phone per shop in 30 minutes, at most 30 orders per shop
     per minute → `rate_limited`.
  3. Settings (`for update` when placing only); fulfillment switch → `fulfillment_unavailable`; `accepting_orders` false →
     `shop_closed`. Walk-in, delivery and ASAP pickup need `private.is_open_now` (`shop_closed`) and not busy
     (`shop_busy`). A pickup time must be at least 15 minutes ahead, today or tomorrow (Manila), inside business
     hours, and not on a closure → `pickup_time_invalid`.
  4. Payment rules: walk-in → cash or a transfer; pickup → a transfer, or cash when `pay_later_pickup`; delivery →
     a transfer, or `cod` when `cod_enabled` (`cod_not_allowed`). A transfer needs an active account of that
     method → `payment_unavailable`.
  5. Customer (place only): find by `(tenant_id, phone)`; create a guest row if none. Never overwrite a member's
     name or email from a checkout. (P5.5 adds the signed-in member path.)
  6. Lines: when placing, lock every variant once in id order; then per line: active item, variant not archived, not sold out
     (`item_unavailable`, detail = variant id); option ids unique, each in a group linked to the item, not sold out,
     every group's min/max respected (`invalid_options`); unit price from the variant, `options_total` from the
     options; stock checked across lines of the same variant (`out_of_stock`, detail = variant id). In quote mode
     collect these as `problems` (`lineIndex`, code) and keep going; in place mode raise.
  7. Delivery: zone required unless `delivery_fee_via_messenger` (`zone_required`); zone active and in this shop
     (`zone_invalid`); fee from the zone (0 when confirmed on Messenger).
  8. Reward: `useReward = true` → `reward_unavailable` (P5.5 replaces this).
  9. Totals; place only: counter upsert for the Manila business date, order row, lines, stock decrement (variant
     `is_sold_out` stays as the owner set it; the storefront treats `stock_on_hand = 0` as sold out), a
     `status` event (`actor customer`), a `privacy` consent row, and `expires_at = now() + unpaid_expiry_minutes`
     for transfer orders only (cash and COD never expire on their own). A zero total is paid at once.
- `public.quote_order(p_slug text, p_payload jsonb) returns jsonb`: calls `build_order` in quote mode, which
  takes no locks and writes nothing. `anon` + `authenticated`.
- `public.place_order(p_slug text, p_payload jsonb) returns jsonb`: the reference's retry logic: the same
  `clientKey` in the same shop returns the first order (no throttle, no stock); two calls at once lose on the
  unique index and get the first order. Returns `{ orderId, orderNo, token }`. Token: 16 random bytes,
  base64url, no padding (`extensions.gen_random_bytes`). `anon` + `authenticated`.
- `public.submit_payment_proof(p_token, p_method, p_reference_no, p_proof_path) returns jsonb`: trimmed from the
  reference. Order `placed` and `unpaid`, else `order_not_payable`; method is a transfer with an active account;
  reference 4 to 40 chars, normalised (`upper`, no spaces or dashes); duplicate in this shop →
  `duplicate_reference`; path matches `<tenant_id>/<token>/<uuid>.webp` and the object exists in `storage.objects`
  (`proof_missing`); at most 3 proofs per order (`too_many_proofs`). Inserts a pending payment, sets the order's
  payment status `pending`, method, `expires_at = null`, and a `payment_submitted` event. `anon` + `authenticated`.
- `public.get_order(p_token text) returns jsonb`: `OrderReceipt` (order, lines, events oldest first, payments
  without `reference_norm`). Unknown token → `not_found`. `anon` + `authenticated`.
- `private.order_accepts_proof(p_tenant uuid, p_token text) returns boolean` for the storage policy.

### 3. Storage policy for proofs

`payment-proofs` insert for `anon` and `authenticated` when folder 1 is a tenant id, folder 2 is a token, and
`private.order_accepts_proof(...)` is true (so only someone holding the receipt link can upload, and only while
the order waits for payment). `select` only for `private.is_shop_member(folder 1)` (owners view through signed
URLs). No update or delete for clients.

### 4. Live updates (realtime broadcast)

Trigger `after insert or update of status, payment_status on orders` calling `private.broadcast_order()`:
- `realtime.send(jsonb_build_object('status', ..., 'paymentStatus', ...), 'order_changed', 'order:' || token, false)`
  (a public topic: the token is the secret).
- `realtime.send(jsonb_build_object('orderId', ..., 'op', lower(TG_OP), 'status', ..., 'paymentStatus', ...),
  'order_changed', 'shop:' || tenant_id, true)` (private).
- Policy on `realtime.messages` for `authenticated`, `select`: topic starts with `shop:` and
  `private.is_shop_member(private.try_uuid(split_part(realtime.topic(), ':', 2)))`.

### 5. `packages/api` slice 3

Every name in `docs/api-surface.md` slice 3. `useOrderLive(token)` joins `order:<token>` and invalidates
`qk.order(token)` on each message; while the channel is not `SUBSCRIBED` it refetches every 15 s (paper 10). The
`shop:` channel hook ships in P5.4 but the trigger is here. `useMyOrderTokens(slug)` keeps the last 20 tokens per
shop in localStorage (wrapped in try/catch). `usePlaceOrder` keeps the same `clientKey` across retries of one
checkout and makes a new one only after success.

### 6. Tests

pgTAP `04_orders.test.sql`, at least:
1. Quote and place give the same totals; a payload price field is ignored (prices come from the database).
2. A hidden item, an archived variant, a sold-out option, a wrong option count and too little stock each appear
   in `problems` with the right `lineIndex`, all in one quote; `place_order` raises the first.
3. Two lines of the same variant are counted together against stock.
4. Order numbers per shop per day are 1, 2, 3 with no gap after a failed placement in between.
5. The same `clientKey` twice returns the same order and moves stock once.
6. Payment rules per fulfillment, COD switch, pay-later pickup switch, closed shop, busy shop, pickup time rules.
7. The 4th unpaid order from one phone in 30 minutes raises `rate_limited`.
8. A proof with a reference already used in that shop (spaces and dashes ignored) raises `duplicate_reference`;
   after the first is rejected (set by hand in the test) the reference is usable again.
9. Proof path checks and the storage insert policy: a stranger with the wrong token cannot upload.
10. `anon` cannot select `orders`, `customers` or `payments`; owner A cannot see shop B's orders; owners cannot
    insert or update orders directly.
11. Realtime: the broadcast trigger runs without error (assert a row lands in `realtime.messages` when available
    locally; otherwise assert the function exists and say so).

Vitest: payload builders, error mapping, the clientKey retry behaviour of `usePlaceOrder` (mocked client).
