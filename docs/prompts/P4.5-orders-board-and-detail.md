## Goal

The owner never misses an order: new orders arrive live with a chime, each card has exactly one next step, payment proofs are checked in the order detail, and every order can be finished or cancelled from a phone.

## Read first

`CLAUDE.md`, `docs/ux-plan.md` sections 3, 5.9 to 5.11 and 7, the order hooks P5.4 added, `packages/core/src/order-rules.ts`, the P4.0 patterns. Plan first; stop and say what is missing if a hook isn't there.

## Build only

In `apps/dashboard/src/features/orders/` and the shell (`src/app/shell/`) for the count, title and sound:

1. **Board** (`orders`): columns New, Preparing (Kitchen/Packing word from `VOCAB`), Ready, Out, Done today. Phone: `tabs` with counts. Tablet: 2 to 3 columns. Laptop: 4 to 5 columns. Desktop ≥ 1280: board + the selected order's detail in a side panel. Cards are `OrderCard` from `packages/ui`; the primary button comes only from `nextActions()`.
   - Next step is optimistic with an "Undo" toast for 5 s (Undo calls the reverse step only where the server allows it; otherwise no Undo). Errors revert the card and say why.
   - Search by order number or name; "Find by number" for the counter.
   - Live with `useShopOrdersLive`: new order → card appears, chime, and the shell's Orders count and tab title "(2) Orders · Juan's Café" update. A "Turn on order sound" chip until the owner taps once (browsers block sound before that).
   - Offline or realtime lost: `OfflineBanner` + Refresh.
2. **Order detail** (`orders/$orderId`, also the side panel): header (`#042`, type, `OrderStatusBadge`, age), customer with Call (`tel:`) and Message (m.me or SMS), Member badge, address and landmark, `OrderLines`, totals, payment card: method, `PaymentBadge`, proof (tap to zoom in a `ResponsiveDialog`), reference with `CopyButton`, the rule "A screenshot is not proof. Check this reference in your own GCash or Maya app.", Approve / Reject with a reason. Cash: "Mark paid". Out for delivery asks for an optional tracking link. Vertical `OrderTimeline` with times. `StickyActionBar` with the next step. "⋯": Cancel (reason required, `alert-dialog`), Print slip.
3. **Print slip:** a print-only layout (80 mm friendly): shop name, `#042`, type, time, lines, total, payment, "ORDER SLIP · NOT AN OFFICIAL RECEIPT".

## Do not build

- Kitchen display, drag and drop, bulk actions, QR scanner (roadmap 1), Bluetooth printers, staff assignment, order editing.

## Rules

- `pnpm check` green. Test that the board's columns and buttons come only from `packages/core` (no status logic in the feature).
- No new packages. No `any`, no casts, no `@ts-ignore`. Never read or print `.env.local`.

## Done when (I will test on a phone with Juan's Cafe and Tala Apparel)

- With the dashboard open on one phone, I place an order on another: it appears within seconds with the chime, and the tab title count goes up.
- Walk-in cash: Mark paid, Start, Mark ready, Complete; the customer's receipt follows live.
- GCash proof: I zoom the proof, Approve, and the order moves on; Reject with a reason shows that reason on the receipt.
- Delivery COD: Out for delivery with a tracking link, then Complete.
- Cancel asks for a reason, returns stock (check the product), and the receipt shows Cancelled.
- Print slip prints one clean page with the "not an official receipt" line.
- 390 px with no sideways scroll, light and dark, 0 console errors. `pnpm check` is green.
