## Goal

Anyone can open `shop.webserbisyo.com/juans-cafe` and the storefront reads the real shop from the database in one
call, and both demo shops have a realistic catalog created by one line in the SQL editor, with no AI tokens.

## Build only

### 1. Migration `<timestamp>_storefront_read.sql`

`public.get_storefront(p_slug text) returns jsonb`: `security definer`, `stable`, `set search_path = ''`, execute
granted to `anon` and `authenticated`.
- Only `active` shops; anything else raises `shop_not_found` (pending and suspended shops are invisible).
- Returns the `Storefront` contract: the shop **without** `plan`, `paid_until` and `status` (add `PublicShop` to
  core and use it in `Storefront`; nobody outside the shop should see billing), its settings, `isOpen`
  (`private.is_open_now` and `accepting_orders` and not busy), hours, closures from today on, categories not
  hidden (with `icon`), items with `status = 'active'` (photos in order, variants not archived, option groups with
  options), active payment accounts, active zones, `stampRule` null (P5.5 replaces this function), `memberCount`
  null when `show_member_count` is off, else 0 (real count in P5.5).
- One query per section with `jsonb_agg` ordered by `sort, name`; no loops. Keys are camelCase in the JSON so the
  core schema parses it directly.
- Index check: `explain` the function's queries on the demo data and add any missing index.

### 2. Demo shops (Appendix B, catalog part)

Migration `<timestamp>_demo_tools.sql`, functions in `private` (execute granted to nobody, so only the SQL editor
and `seed.sql` can run them; `security definer` is not needed):
- `private.demo_setup()` calls the two below for `juans-cafe` (food, "Juan's Cafe") and `tala-apparel` (retail,
  "Tala Apparel").
- `private.demo_ensure_shop(slug, name, business_type, colours)`: if the slug exists, keep it and its owner
  (it is probably the shop I created in P3b); else create the tenant with no owner. Either way set `is_demo = true`,
  `status = 'active'`, `plan = 'demo'`, `paid_until = current_date + 365`, settings filled (tagline, phone, city,
  Messenger username `smartappph`, colours, delivery on, COD on for Tala, `pay_later_pickup` on for Juan's), hours.
- `private.demo_seed_catalog(slug)`: refuses unless `is_demo`; replaces only the catalog of that shop (no orders
  exist yet; P5.6's `demo_reset` handles orders). Realistic Philippine data, prices in centavos:
  - Juan's Cafe: categories Coffee, Milk tea, Pastries, Rice meals, each with a Fluent icon key from
    `FLUENT_ICONS` if it exists by then (else an emoji). About 16 items: Iced Latte (Regular ₱120, Large ₱150),
    Spanish Latte, Americano, Wintermelon and Okinawa milk tea (Medium ₱99, Large ₱119), Ube Cheese Pandesal,
    Ensaymada ₱45, Chicken Adobo rice ₱149, Tapsilog ₱159 and similar. Option groups: Sugar level (required, pick 1:
    0/25/50/75/100%), Add-ons (optional, up to 2: Extra shot ₱30, Oat milk ₱25, Pearls ₱15). Stock tracking on
    the pastries only (Ensaymada 3, one item sold out). GCash and Maya accounts (names and numbers clearly fake,
    for example `0917 000 0001`), three zones (Poblacion ₱50, Barangay San Roque ₱70, Outside town: fee on
    Messenger off), hours 07:00 to 21:00.
  - Tala Apparel: categories Tops, Dresses, Bottoms, Accessories. About 14 items with size variants S/M/L/XL and
    stock on every variant (some at 1 to 2 for low stock, one at 0), a Color option group on two items, bank
    (BPI, fake number) and GCash accounts, zones Metro Manila ₱120 and Provinces ₱250, hours 10:00 to 19:00, closed
    Sundays.
  - No photos (the screens show the placeholder); `is_featured` on 4 to 6 best sellers per shop.
- `supabase/seed.sql` (local `db reset` only): `select private.demo_setup();`.
- `supabase/snippets/founder.sql`: add "Demo shops: set up or refresh catalog" (`select private.demo_setup();`)
  and "Make me the owner of a demo shop" (insert into `tenant_members` for a slug and an email, skipping if the
  shop already has an owner), with one comment line each.

### 3. Storefront wiring (data only)

- `packages/api`: `getStorefront(client, slug)` (returns `null` for `shop_not_found`), `useStorefront(slug)`,
  `qk.storefront(slug)`. Parse with the `Storefront` schema.
- `apps/storefront`: replace the stub in `src/features/shell/shop.ts` with `getStorefront` through
  `createPublicClient` and React `cache()` (one call per request for layout, metadata and page). Unknown slug →
  `notFound()`. Theme colours come from the real settings. Delete `packages/api/src/stubs.ts` and its test.
  Shop pages stay dynamic for now (owner edits must show within seconds); caching is P6.
- `apps/storefront/src/app/[shop]/manifest.webmanifest/route.ts`: per-shop web app manifest (name, short name,
  `start_url` and `scope` `/<slug>`, `display: standalone`, theme and background from the shop colours, icons from
  the logo thumb or the platform icon). Link it from the shop layout's metadata. Per-shop generated icons are P6.

### 4. Tests

- pgTAP `03_storefront_read.test.sql`: `anon` can call `get_storefront` for an active shop; pending and suspended
  raise `shop_not_found`; hidden items, hidden categories, archived variants, inactive accounts and zones are left
  out; no `plan` or `paid_until` key in the result; `memberCount` is null when hidden; the open-hours cases from
  `packages/core/src/test/open-cases.ts` give the same answers in `private.is_open_now` (copy them as SQL rows;
  a Vitest test fails if the two lists differ in length); `demo_seed_catalog` refuses a shop with `is_demo = false`;
  `anon` and `authenticated` cannot execute the demo functions.
- Vitest: `getStorefront` parses a recorded result of `demo_setup` (fixture JSON) with the core schema.

## By hand after the merge (step by step)

1. Wait for GitHub → Actions → `db-deploy` to finish green.
2. Supabase → SQL Editor → New query → paste `select private.demo_setup();` → Run. It should say "Success".
3. If your P3b shops were `juans-cafe` and `tala-apparel`, you are already their owner. If not, run the
   "Make me the owner of a demo shop" snippet with your email.
4. Open the storefront preview link for `/juans-cafe` and `/tala-apparel`.
