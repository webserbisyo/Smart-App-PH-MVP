## Goal

The owner can verify or reject a proof, mark a cash order paid, move an order one step at a time, cancel with a
reason (stock comes back), and hears every new order; unpaid transfer orders expire on their own; every money
decision is logged. The same rules decide the board's one next-step button in `packages/core`.

## Build only

### 1. Migration `<timestamp>_owner_orders.sql`

- `audit_log` (paper 7.3; append-only): owners `select` their shop's rows; no client writes.
- Every function below: `security definer`, `set search_path = ''`, finds the order's shop from the row and
  requires `private.is_active_shop_owner` (`not_allowed`, the same answer whether or not the id exists), locks the
  order row first and then its payments (one lock order everywhere, as the reference does), writes an
  `order_events` row with `actor owner`, and an `audit_log` row for payment decisions and cancels. Execute for
  `authenticated` only.
- `review_payment(p_payment_id, p_approve, p_reject_reason)`: payment must be `pending`
  (`payment_not_pending`); order not cancelled or expired (`order_not_payable`). Approve → payment `confirmed`,
  order `paid`, `paid_at`, event `payment_confirmed`. Reject (reason 3 to 200 chars) → payment `rejected`, order
  payment status back to `unpaid`, `expires_at = now() + unpaid_expiry_minutes`, event `payment_rejected` with the
  reason as note (the receipt shows "Payment not accepted" and the reason).
- `record_payment(p_order_id, p_method)`: method `cash`, or `cod` for delivery orders; it becomes the order's
  method (a GCash customer who pays cash at the counter is recorded as cash); order not
  already paid (`already_paid`) and not waiting on a proof (`payment_not_pending`); inserts a `confirmed` payment of
  the order total and marks the order paid.
- `advance_order(p_order_id, p_to_status, p_tracking_url)`, transitions (paper 6.9):
  - `placed → preparing` only if paid, or the method is `cash` (walk-in, or pickup with `pay_later_pickup`) or `cod`;
  - `preparing → ready` (`ready_at`); `ready → out_for_delivery` for delivery only (optional `https://` tracking
    URL); `ready → completed` for walk-in and pickup; `out_for_delivery → completed` for delivery;
  - `completed` requires `payment_status = 'paid'` (`not_paid`): the board's button for an unpaid cash order is
    Mark paid first;
  - on `completed`: `completed_at`, and the customer's `order_count + 1`, `total_spent + total`, `last_order_at`;
  - anything else → `invalid_transition`.
- `cancel_order(p_order_id, p_reason)`: from `placed`, `preparing`, `ready`, `out_for_delivery`; reason 1 to 200;
  returns tracked stock for every line whose variant still exists; pending payments become `rejected` with
  "Order cancelled"; a paid order keeps its confirmed payment and the event note says the refund is by hand.
  (P5.5 adds stamp reversal.)
- `set_stock` (from P5.1) now writes an `audit_log` row (replace the function, same signature).
- `private.expire_unpaid_orders() returns jsonb`: `placed`, `unpaid`, `expires_at < now()` → `expired`, stock
  returned, event `actor system`; returns `{ expiredCount, ranAt }`. Not callable by clients.
- `create extension if not exists pg_cron;` and
  `select cron.schedule('expire-unpaid-orders', '* * * * *', 'select private.expire_unpaid_orders()');`
  (idempotent: unschedule first if it exists).
- Realtime: the `shop:` broadcast already fires from P5.3's trigger; nothing new in SQL.

### 2. `packages/core` order rules

Port and trim `status.ts` and `order.ts` from the reference into `packages/core/src/orders/`:
- `boardColumn(order)` → `new | preparing | ready | out | done`;
- `nextActions(order, settings)` → the allowed steps, main step first, from `verify_payment | mark_paid | start |
  mark_ready | out_for_delivery | complete`, matching the SQL rules above exactly; a test walks every fulfillment and
  payment method from `placed` to `completed` to prove every open order can be finished (the first build's Home
  could not finish delivery orders);
- `timelineSteps(order, events)` for the receipt and detail timelines;
- `canCancel(order)`, `isLate(order, now)` (pickup time passed or waiting over 15 minutes), status and payment
  labels and tones (green paid/done, amber waiting/to verify, red late/problem; paper 9.1) as word keys.
- `packages/core/src/test/transition-cases.ts`: one table of (order state, settings, action → allowed or error
  code). Vitest runs it against `nextActions`; the pgTAP test runs the same rows against `advance_order` and
  `record_payment` (copied as SQL rows; a Vitest check fails if the counts differ).

### 3. `packages/api` slice 4

Every name in `docs/api-surface.md` slice 4.
- `useOrders(tenantId, scope)`: `open` = not completed, cancelled or expired, plus today's done; `day` = one
  Manila date. Selects orders with their `order_items`; maps to `BoardOrder`.
- `useShopOrdersLive(tenantId, callbacks)`: `client.realtime.setAuth()` then a private channel `shop:<tenantId>`;
  on each message invalidate `qk.orders(tenantId)` and `qk.dashboardToday(tenantId)`, call `onNewOrder` for
  inserts and `onToVerify` when `paymentStatus` becomes `pending`; while not `SUBSCRIBED`, refetch every 15 s
  (paper 10). The chime sound itself is a screen concern (P4.4).
- `useAdvanceOrder` is optimistic (moves the card at once, rolls back on error).
- `useProofUrl(path)`: `createSignedUrl` for 300 s.

### 4. Tests

pgTAP `05_owner_orders.test.sql`: every row of `transition-cases`; approve and reject flows (reject reopens the
expiry and frees the reference); `record_payment` rules; cancel returns stock exactly once and never below what
was taken; owner B gets `not_allowed` on every function for shop A's order; a pending shop's owner gets
`not_allowed`; `expire_unpaid_orders` expires only transfer orders past `expires_at` and returns their stock;
cash and COD orders never expire; customer stats move only on completion; audit rows exist for approve, reject,
record, cancel and `set_stock`; clients cannot execute `private.expire_unpaid_orders`.

Vitest: `transition-cases`, `boardColumn`, `isLate`, the live hook's fallback timer (fake timers, mocked channel).
