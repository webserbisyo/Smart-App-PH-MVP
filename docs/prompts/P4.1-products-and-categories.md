## Goal

An owner can add, edit, sort, hide and sell out products and categories from a phone, with photos, variants, stock and add-ons, and every change shows in the database at once.

## Read first

`CLAUDE.md`, `docs/ux-plan.md` sections 3, 5.12 and 7, `docs/api-surface.md` slice 1 (the hooks P5.1 added), and the P4.0 patterns on `/kit`. Start with a short plan that lists every file and every hook you will call; if a hook you need is missing, stop and say which.

## Build only

In `apps/dashboard/src/features/products/` (screens, components, `module.ts`):

1. **Products list** (`products`): grouped by category (collapsible), search, rows with photo or `CategoryIcon`, name, price range (`Money`), stock ("3 left" amber at or below the low-stock number), inline Visible and Sold out switches (optimistic, toast on error with the switch reverted). "Add" in the top bar; on phones a `StickyActionBar` button. `QueryState` for loading, empty ("Add your first item" with the vocab word), error, offline.
2. **Categories** (`products/categories`): `sortable` list with `CategoryIcon`, name, hidden switch, product count. Add and edit in a `ResponsiveDialog`: name and the icon picker (tabs Icons / Emoji / Photo). Icons: a searchable grid of `FLUENT_ICONS` (search by name and words). Emoji: a text field limited to one emoji. Photo: `PhotoField` (512 px square). Delete only when empty (`useRemoveCategory` refuses with `category_not_empty`; show its words).
3. **Product editor** (`products/new`, `products/$itemId`), React Hook Form + Zod schema from `packages/core`:
   - Photos: `PhotoField`, up to 5, `sortable`, first is the cover.
   - Name, category (`native-select`, with "New category" opening the dialog), description.
   - Variants: rows of name, `PesoField`, stock (when tracking is on), sold out. One row means "no options" for the customer and hides the name field.
   - "Track stock" switch and low-stock number.
   - Add-on groups (collapsible, closed until used): name, required, max choices, options with name and price.
   - Visible and Best seller switches.
   - `StickyActionBar` with Save; unsaved changes ask before leaving. Delete uses `useDeleteItem`; when it answers `item_has_orders`, offer Archive (`useSetItemStatus`) instead. Saving is one `useSaveItem` call; photos upload first with `uploadShopMedia` and show with `mediaUrl`.
4. Errors show `errorWords(code, vocab)` from core, never raw database text. Labels use `VOCAB` (Menu item / Product) and `WORDS`; never check the business type.

## Do not build

- No storefront screens (P4.3), no bulk edit, no CSV import, no barcode, no price history, no image cropper.

## Rules

- `pnpm check` green. Test the editor form's Zod mapping (variants, add-on limits) in the feature.
- No new packages. No `any`, no casts, no `@ts-ignore`. Never read or print `.env.local`.
- Dashboard features never import each other; anything shared goes to `packages/ui`.
