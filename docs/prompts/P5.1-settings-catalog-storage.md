## Goal

An active owner can read and change everything a shop is made of (hours, closed days, payment accounts, delivery
zones, categories, items, variants, add-ons, photos) through `packages/api`, safely, with the database refusing
every cross-shop write. No screens.

## Build only

### 1. Migration `<timestamp>_settings_and_catalog.sql`

Tables (paper 7.3 names and columns), each with `tenant_id uuid not null references tenants on delete cascade`,
RLS on, explicit grants:

- `business_hours` (pk `tenant_id, weekday`; `opens_at time`, `closes_at time`, `opens_at <> closes_at`;
  overnight allowed when `closes_at < opens_at`), `closures` (pk `tenant_id, closed_on`, `note` max 80).
- `payment_accounts` (method check `('gcash','maya','bank')`, `bank_name` required when bank), `delivery_zones`
  (`fee` integer ≥ 0, name max 60, `eta_text` max 40).
- `categories` with `icon_kind text` check `('fluent','emoji','image')` and `icon_value text`, both null or both set
  (decision UI-3); `items`; `item_photos`; `item_variants` (`price integer ≥ 0`, `stock_on_hand integer ≥ 0` or
  null, `low_stock_at`); `option_groups` (`min_select ≥ 0`, `max_select ≥ 1`, `max_select ≥ min_select`);
  `options` (`price_delta integer ≥ 0`); `item_option_groups` (pk `item_id, group_id`).
- **Cross-shop safety (a bug class the first build had):** every parent gets `unique (id, tenant_id)` and every
  child references it with a composite foreign key, for example `foreign key (category_id, tenant_id) references
  categories (id, tenant_id)`. RLS checks the row's own `tenant_id`; the composite key makes sure the parent it
  points to is in the same shop. Applies to items→categories, photos/variants→items, options→option_groups,
  item_option_groups→items and option_groups.
- Indexes on every foreign key and on `(tenant_id, sort)` where lists are sorted.
- `sort integer not null default 0` where paper 7.3 has `sort`.

Policies and grants (`authenticated` only; `anon` gets nothing, the storefront reads through `get_storefront` in
P5.2, which also keeps hidden items private):
- `select` for `private.is_shop_member(tenant_id)`; `insert`, `update`, `delete` for
  `private.is_active_shop_owner(tenant_id)` (with `with check` on insert and update).
- `item_variants`: column grant `update` on every column except `tenant_id`, `item_id` and `stock_on_hand`. Stock
  changes only through functions (decision D6).

Functions (`set search_path = ''`, explicit grants to `authenticated` only; add each contract to `db-functions.ts`):
- `save_item(p_item jsonb) returns jsonb`, **`security invoker`** (RLS still applies), one transaction: upsert the
  item, its variants (at least one; variants missing from the payload get `archived_at = now()`, never deleted),
  photo paths in order (each path must start with `<tenant_id>/items/`), and option group links. Returns the
  `CatalogItem`. Raises `invalid`, `variant_required`.
- `set_stock(p_variant_id uuid, p_stock_on_hand int) returns item_variants`, `security definer`, owner of an
  active shop only (`not_allowed`). Also clears `is_sold_out` when stock goes above 0 by hand. (P5.4 adds the audit
  log line.)
- `save_sort_order(p_kind text, p_ids uuid[])`, `security invoker`: rewrites `sort` for the listed rows, all in one shop.
- Replace `create_my_shop` (same signature) to also insert default hours: every day 08:00 to 20:00.
  Update its comment in `db-functions.ts` (decision P3-3 is now done).
- `private.is_open_now(p_tenant_id uuid) returns boolean` (copy and trim from the reference migration
  `20261004145146_db_v1_fixups.sql`): Manila time, closures first, overnight hours, a shop with no hours rows is
  closed (not open; the reference got this backwards for a shop that removed all its days).

Storage (in the same migration):
- Buckets by `insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)`:
  `shop-media` public, 2 MB, `image/webp`, `image/png`, `image/jpeg`; `payment-proofs` private, 1 MB, `image/webp`,
  `image/jpeg`.
- `shop-media` policies on `storage.objects`: insert, update and delete for `authenticated` when
  `private.is_active_shop_owner(private.try_uuid((storage.foldername(name))[1]))`. No select policy (public URLs
  work without one, and nobody can list another shop's files).
- `payment-proofs` policies come in P5.3 with the orders table.

### 2. `packages/core`

- `Category` gets `icon: CategoryIcon` (`{ kind: 'fluent', key } | { kind: 'emoji', value } | { kind: 'image',
  path } | null`); `ItemDraft` and `CatalogItem` schemas; `SortKind`.
- `openState(hours, closures, now)` → `{ isOpen, closesAt, nextOpensAt }` in Manila time (copy helpers from
  `reference/packages/core/src/commerce/time.ts`). One table of cases (overnight, closure today, no hours, Sunday
  to Monday) lives in `packages/core/src/test/open-cases.ts`; the Vitest test runs it, and P5.2's pgTAP test runs the
  same cases against `private.is_open_now`.
- `formatPeso` and centavo helpers from `reference/packages/core/src/money.ts` if not there yet.
- New error codes in `contracts/errors.ts`: `variant_required`, `category_not_empty`, `not_allowed`, `invalid`.

### 3. `packages/ui/src/lib/image.ts`

`compressImage(file, { maxSize, quality })` → WebP `Blob`, copied and trimmed from `crop-image.ts` (browser canvas,
no Supabase). Sizes: product and cover 1600 px plus a 400 px thumb, logo and category 256 px, QR 1024 px, proof
1600 px. Unit-test the size math only.

### 4. `packages/api` slice 1

Every name in `docs/api-surface.md` slice 1, with mappers, `qk` keys and invalidation.
- `uploadShopMedia(client, tenantId, kind, { full, thumb })` writes `<tenantId>/<kind>/<uuid>.webp` and
  `<uuid>-thumb.webp`, `upsert: false`, `cacheControl: '31536000'` (paths never change, so images cache forever).
- `mediaUrl(path, size)` uses `getPublicUrl` and the `-thumb` suffix for `thumb`.
- Removing a photo, logo or QR deletes the storage object too (owner policy allows it).
- `useDeleteItem` is a plain RLS delete (variants, photos and links cascade); from P5.3 the database refuses it for
  items with orders (`item_has_orders`).

### 5. Tests

- `supabase/tests/database/02_settings_and_catalog.test.sql`: owner A can write every table in shop A; cannot read
  or write shop B's rows; cannot point an item at shop B's category or a link at shop B's option group (composite
  key error); cannot update `stock_on_hand` directly; `set_stock` works for A and raises `not_allowed` for B and for
  a pending shop; `save_item` with no variant raises `variant_required`; `anon` cannot select any of these tables;
  a storage insert into `shop-media/<shop B id>/…` as owner A is refused; a new shop gets 7 default hours rows.
- Vitest: mappers, `openState` cases, image size math.

## Do not build

- No screens (P4.1). No `get_storefront` (P5.2). No orders, customers or loyalty tables. No image CDN or server-side
  resizing (Supabase image transforms are Pro only; the browser makes both sizes).

## Rules

`pnpm check` and `pnpm db:test` green; `pnpm db:types` regenerated and committed. No new npm packages. RLS, grants
and policies in the same file. Never edit an applied migration. Add to `docs/decisions.md` "## Phase 5":
- P5-1: Composite foreign keys keep every child row in its parent's shop.
- P5-2: Stock changes only through `set_stock` and the order functions; prices and names are plain owner edits.
- P5-3: Images are compressed in the browser to two WebP sizes; `shop-media` paths are immutable and cached for a year.
