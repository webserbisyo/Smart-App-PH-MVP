# Checkpoint P4.0: Kit additions and shared patterns

Build Plan v1.1, Phase 4 (reworked by `docs/ux-plan.md`). System paper 9.1, 9.2, 6.9. No screens and no data: building blocks only, shown on the dashboard `/kit` page.

Runs after P3b. It does not need any P5 checkpoint, so it can run while P5.1 is being built.

To run it, paste this one line into a Claude Code session on `webserbisyo/Smart-App-PH-MVP`:

> Read docs/prompts/P4.0-kit-and-shared-patterns.md and do exactly that checkpoint.

The cloud environment must allow `ui.shadcn.com` and `diceui.com` (project default environment "smartapp-p2" does). If `shadcn add` gets a 403, stop and say so.

---

## Goal

Every part that more than one screen needs exists once, in `packages/ui` or `packages/core`, with all its states visible on `/kit`, so P4.1 to P4.7 only assemble screens.

## Read first

`CLAUDE.md`, `docs/ux-plan.md` (sections 1 to 4 and 7), `docs/api-surface.md` (names shared with the backend checkpoints), `docs/ui-kit.md`, `reference/README.md`. Start with a short plan that lists every file, then build.

## Build only

### 1. Install (pre-approved by the founder, decision F2)

Into `packages/ui` with `pnpm dlx shadcn@4.21.4 add …`:
- DiceUI: `@diceui/responsive-dialog`, `@diceui/qr-code`, `@diceui/stat`, `@diceui/status`, `@diceui/scroller`
- shadcn: `progress`
- npm: `qrcode` 1.5.4 (and `@types/qrcode` as a dev dependency if the component needs it) in `packages/ui`

Fix every cast and lint error in the new files the way P2 did (no `as`, no `any`, no `eslint-disable`). Add each to `docs/ui-kit.md` (component → screen) and `docs/stack-versions.md`. Kit total becomes 57.

### 2. Core rules (`packages/core`, pure TypeScript, with tests)

Copy and trim from `reference/` (reuse a file if a backend checkpoint already added it; never make a second one):
- `src/money.ts`: `formatPeso` (₱120, ₱1,234.50, never ₱120.00), `parsePesoInput` (accepts "₱120", "120.50", "1,200"), `sumCentavos`.
- `src/time.ts`: Manila business date, `formatManilaTime` ("3:30 PM"), `minutesSince`, `ageLabel` ("4 min", "1 hr 5 min").
- `src/status-look.ts`: `STATUS_LOOK`, order status and payment status → tone (`success | warning | danger | info | neutral`), icon key and word key. Only how a status looks; which step comes next is not here.
- The order rules (`nextActions`, `boardColumn`, `timelineSteps`, `canCancel`, `isLate`) are **not** built here: P5.4 adds them to core to match the SQL. The patterns below take their results as props.
- `src/phone.ts`: `normalizePhPhone` (0917…, 917…, +63 917… → `+639171234567`) and `formatPhPhone`.
- Words: add every new label to `src/words.ts`. No arrows, emoji or symbols inside words.

### 3. Fluent category icons (decision UI-3)

Copy `reference/packages/ui/src/assets/objects/` (110 WebP files, `index.ts`, `LICENSE.md`) to `packages/ui/src/assets/fluent/`. Rename the export to `FLUENT_ICONS`: key → `{ url, name, words[] }` (search words in English plus a few Filipino ones where natural: kape, tinapay, damit, sapatos). Add `isFluentKey`. Check the files load in both Vite and Next (literal `new URL(…, import.meta.url)`).

Add `CategoryIcon` to `packages/core`'s `Category` schema only if P5.1 has not: `icon: { kind: 'fluent', key } | { kind: 'emoji', value } | { kind: 'image', path } | null`.

### 4. Image compression

Copy `reference/packages/ui/src/lib/crop-image.ts` to `packages/ui/src/lib/image.ts` (the name `docs/api-surface.md` uses; reuse it if P5.1 already made it): `compressImage(file, { maxSize, square })` → WebP Blob (1600 px for photos, 512 px square for logos and category photos, about 200 KB for proofs). Unit-test the size maths.

### 5. Shared patterns (`packages/ui/src/patterns/`)

Build each from `docs/ux-plan.md` section 4.3. Props in, events out; words come in as props from `WORDS`; no data fetching, no `@smartapp/api`, no business type checks.

`Money`, `StatusBadge` (`OrderStatusBadge`, `PaymentBadge`), `QueryState`, `OfflineBanner` (+ `useOnline` hook), `StickyActionBar` (safe area, rides above the keyboard with `use-keyboard-open`), `QuantityStepper`, `PhoneField`, `PesoField`, `CopyButton`, `CategoryIcon`, `PhotoField` (takes `upload(blob) => Promise<string>`, shows progress, retry, remove; copy-and-trim `reference/.../uploads/queue.tsx`), `OrderLines`, `OrderTimeline` (ReUI timeline, horizontal or vertical; takes the steps as a prop), `OrderCard` (normal and compact; takes `actions` as a prop, shows the first as the one full-width button and the rest under "⋯"), `StampCard` (stamps as filled/empty circles in member green, "2 more to …" line, reward-ready state with one confetti burst), `ShopHeader`, `ProductCard` (photo or category icon fallback, from-price, sold-out state, "+" button), `SettingsSection`, `ShareShop` (link + `CopyButton` + QR download).

Replace the two cart overlays in `apps/storefront/src/features/shell/StoreNav.tsx` with one `ResponsiveDialog` (right side on desktop, bottom sheet on phones).

### 6. `/kit` page

Add a "Patterns" section: each pattern in each state (loading, empty, error, offline, long name, ₱12,345, sold out, every order status × fulfillment, every payment status, stamp card at 0, 7 of 10 and reward ready), light and dark. The sample values live in the kit file only (they are demos, not a mock data layer).

## Do not build

- No screens, routes, hooks or Supabase calls.
- No mock data in `packages/api`.
- No stepper, cropper, carousel or extra registries (`docs/ux-plan.md` 4.2).

## Rules

- `pnpm check` green. Unit tests for every core function above and for `compress-image` maths.
- Only the packages in step 1. No `any`, no casts, no `@ts-ignore`. Never read or print `.env.local`.
- Add to `docs/decisions.md` under a new "## Phase 4" heading: UX-1 to UX-9 from `docs/ux-plan.md` section 1, one line each, plus "P4-1: QR codes use DiceUI qr-code with the `qrcode` package (replaces qrcode.react)". If the founder said no to the welcome stamp (decision F4) or anything in F1 to F3, follow that instead.

## Done when (I will test on a phone)

- `/kit` on a 390 px phone shows every pattern in every state with no sideways scroll, in light and dark.
- `OrderCard` shows one full-width button for the first action it is given and puts the rest under "⋯", in every order status and payment status on `/kit`.
- `StampCard` at reward-ready fires confetti once, and not again on re-render.
- `PhotoField` compresses a 5 MB phone photo to under 300 KB before the (demo) upload.
- The storefront cart opens as a bottom sheet on a phone and a right drawer on desktop, with one overlay.
- 0 console errors and 0 React warnings on `/kit`. `pnpm check` is green.
